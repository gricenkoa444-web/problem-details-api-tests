# Delivery Acceptance API: Problem Details

OpenAPI-спецификация метода приёмки маркированной поставки
`POST /deliveries/{deliveryId}/acceptance` с единой моделью ошибок
по RFC 7807 (Problem Details).

## Что реализовано

- Схема `Problem` в `components/schemas`: поля `type`, `title`, `status`,
  `detail`, `instance` и расширения `reason` (enum) и `violations`.
- Переиспользуемые ответы в `components/responses`, подключаются через `$ref`:
  `400`, `401`, `403`, `404`, `409`, `422`, `429`, `503`.
- Заголовок `Retry-After` для `429` и `503`.
- Тип содержимого ошибок: `application/problem+json`.

## Коды ответов

| Код | Назначение |
|-----|------------|
| 200 | Поставка принята |
| 400 | Некорректная структура или формат запроса |
| 401 | Нет аутентификации |
| 403 | Недостаточно прав |
| 404 | Поставка не найдена |
| 409 | Конфликт состояния (уже принята или отменена) |
| 422 | Нарушение бизнес-правил |
| 429 | Превышен лимит запросов |
| 503 | Сервис временно недоступен |

## Структура

- `openapi.yaml`: спецификация API

## Валидация

```bash
npx @redocly/cli lint openapi.yaml
```
